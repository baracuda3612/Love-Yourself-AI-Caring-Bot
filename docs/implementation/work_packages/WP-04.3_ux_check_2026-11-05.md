# WP-04.3 — інтерактивна UX-перевірка, 2026-11-05

Інструмент: Computer Use / in-app browser із Playwright locators.
Onboarding/menu: реальні production handlers на новій disposable PostgreSQL
базі, з перехопленим Telegram transport, paused scheduler та забороненим Coach.
Веб: реальні HTML renderers/CSP, fixture-only email/code/handoff responses.
Це авторська UX-перевірка, не незалежне code review або фізичний Telegram QA.

## Результат і знахідка

У пройдених сценаріях блокувальної UX-помилки не виявлено. Одна конкретна
неблокувальна знахідка, P3, передана засновнику без автоматичного виправлення.

**UX-01. Людина вводить некоректний час вечірнього нагадування й отримує
загальну підказку з прикладом 14:30, без пояснення, що редагується вечірній
час. Найменше виправлення — залишити вечірній контекст і приклад 18:30
у повідомленні про помилку та повторній підказці.**

Відтворення: Мій розклад → Змінити формат → Підтвердити зміну → 99:99.
Початкове повідомлення: «Введи час вечірнього нагадування … 18:30».
Після помилки: «Введи час у форматі ГГ:ХХ, наприклад 14:30» двічі.
Причина: app/menu_input.py handle_text/pending_screen використовують загальний
текст для day/evening/switch_evening. Власник WP-04.3. Не нова політика часу:
валідація надалі допускає будь-який валідний HH:MM. Статус: засновник прийняв виправлення 2026-11-05. Підказка зберігає
вечірній контекст і 18:30; сценарій перевіряє обидва evening writers.
Повторні перевірки: 68 passed (onboarding/access), 1 passed / 5 deselected
(disposable PostgreSQL scenario).

## Пройдені сценарії

- Вступ → налаштування часу; початкова клавіатура з трьома helper sections.
- 99:99 і довільний текст не просувають setup; валідне 14:34 одразу дає
  три значення й підтвердження, без окремого обов'язкового вибору днів.
- Редактор днів → вибір суботи → Про проєкт → FAQ → стаття → повернення:
  незастосований вибір суботи збережений; скасування повертає пн–пт.
- Редактор часу → 16:10 → актуальна перевірка трьох значень.
- Редактор зони → наступна сторінка → UTC+14 → перевірка; повернення до
  стандартної зони показує Київ.
- Підтвердження → фактичне перше нагадування; після setup є Мій розклад.
  Немає фальшивої Вправи зараз до B6.
- Мій розклад показує час/дні/пояс і наступне нагадування.
- Пауза прибирає обіцянку наступного надсилання; відновлення повертає її.
- Завершення потребує явного підтвердження; скасування залишає розклад активним.
- Мої дані → дозволені редактори без company/access self-edit → ім'я
  «Олена» → актуальні дані.
- Запит копії даних → UUID і строк → Мої звернення показують той самий запит.
- Залишити відгук → явний запит наступного повідомлення → тестовий текст →
  підтвердження збереження; підтримка доступна незалежною кнопкою.
- Перехід 7→14 запитує вечірній час; після 18:30 меню показує два часи.
  Невалідне значення не змінює розклад; контекст помилки — UX-01 вище.
- Активний редактор днів: порожній вибір не приймається; скасування повертає
  розклад. Один початковий непрохід натискання був перекриттям footer самого
  тестового адаптера; його усунено, реальна cancellation підтверджена повторно.
- Відкрито всі 17 поточних статей: 5 опису, 4 про нагадування, 4 FAQ,
  4 конфіденційності; перевірено повернення до підрозділу й Про проєкт.
- Вебвхід: порожній/неправильний email не проходить native validation;
  заповнений email зберігається після відкриття політики в окремій вкладці.
- Екран коду має one-time-code autocomplete; fixture submit відкриває
  handoff з інструкцією Старт/одноразовість/10 хвилин і поверненням до входу.
- Екран недоступного посилання має працездатне повернення до входу.
- DOM підтверджує відсутність overflow на ширинах 390 і 320; вебкнопки
  на мобільному мають висоту близько 51 px; desktop 1280×800 оглянуто в screenshot.

## Межі перевірки

Не виконано: реальний SMTP/OIDC, фактичне погашення посилання в Telegram,
Telegram native keyboard/icon/input behavior, iOS/Android app switching,
експортний файл/повне видалення, B6 voluntary delivery. Нове interactive
проходження не повторювало всі гонки/access-revoke/erasure сценарії: їхні
окремі результати лишаються в WP-04.3_verification.md.

Без production deploy, реальних акаунтів, commit, push або зміни погоджених
product texts. Повторюваний [UX-адаптер та transcript](WP-04.3_evidence/ux-adapter/README.md).
