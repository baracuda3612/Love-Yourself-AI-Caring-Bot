## 1. Доступність

| Стан | Кнопки нижньої клавіатури |
|---|---|
| Налаштування ще не завершені | Мої дані · Про проєкт · Підтримка |
| Налаштування завершені, доступ чинний | Вправа зараз · Мій розклад · Мої дані · Про проєкт · Підтримка |
| Корпоративний доступ закінчився/відкликано | Мої дані · Про проєкт · Підтримка; лише дозволені own-data/rights дії |
| Акаунт уже видалено | Публічна інформація та контакт підтримки; жодного відновлення старих персональних даних кнопкою |

Структура перебудовується за серверними фактами. Старі кнопки й довільний
текст не обходять access/ownership checks. Пауза чи відсутність поточного
циклу після пройденого setup не перетворює людину на нового користувача.
Доставка «Вправи зараз» з'являється лише з готовим B6, без фальшивої кнопки.

Клавіатура відкривається штатною іконкою Telegram біля поля вводу. Нижня
клавіатура — головні розділи, inline-кнопки — вкладені екрани/дії. Команди
не потрібні для звичайного користування. Під вступом/стартовим повідомленням
залишаються погоджені одиничні основні дії. Telegram дозволяє лише один
тип reply_markup на одному повідомленні: під час інтеграції забезпечити
одночасну доступність уже встановленої нижньої клавіатури й inline-дії,
не заявляти, що дві markup-структури можна прикріпити до одного повідомлення.
Варіант фактичного першого прикріплення перевіряє виконавець на пристроях.

## 2. Мапа розділів

```text
Вправа зараз
└─ Пряме отримання вправи через B6, без каталогу/додаткового setup

Мій розклад
├─ На екрані: стан, дні, час, timezone, наступне надсилання
├─ Змінити налаштування
│  ├─ Час доставки вправи
│  ├─ Дні надсилання
│  ├─ Часовий пояс
│  └─ Скасувати / назад без змін
├─ Призупинити або Відновити — залежно від стану
├─ Змінити формат — коли допускає наявний lifecycle
├─ Завершити → явне підтвердження або скасування
└─ Назад до меню

Мої дані
├─ На екрані: ім'я/як звертатися, timezone, компанія, статус доступу
├─ Виправити дані
│  ├─ Як до тебе звертатися
│  ├─ Часовий пояс → той самий редактор, що в налаштуваннях
│  └─ Скасувати / назад без змін
├─ Отримати копію даних → реальний запит, номер і строк
├─ Видалити мої дані → наслідки → підтвердження запиту
├─ Мої звернення → реальні статуси/строки
└─ Назад до меню

Про проєкт
├─ Опис проєкту
├─ Як приходять нагадування
├─ Часті запитання
├─ Конфіденційність → довідкові тексти й актуальне повідомлення
└─ Назад до меню

Залишити відгук → окрема дія з явним надсиланням або скасуванням

Підтримка
├─ Контакт hello@loveyourselfua.com та коротка інструкція
└─ Назад до меню
```

Немає дубля «Зв'язатися з командою». Відгук фіксує думку й не обіцяє
відповіді; підтримка — канал для питання/допомоги. Дані відкриваються одразу,
без окремої кнопки «Переглянути дані». Компанія/статус доступу лише читаються,
відсутні у виборі редагування та заблоковані для self-edit на сервері.

## 3. Повернення до обов'язкового налаштування

До завершення setup всі допоміжні екрани мають **Повернутися до налаштувань**.
Це повернення до того самого питання/редактора, де людина зупинилась, із
прийнятими значеннями й незастосованим вибором днів. Вкладені статті також
мають локальне «Назад», але пряме повернення до setup не змушує йти всіма
рівнями. Після setup замість цього — звичайне повернення до меню.

Повертаємо актуальне повідомлення потрібного кроку в чаті; не обіцяємо
програмно прокрутити Telegram до старого message_id. Ненадісланий текст
поля Telegram серверу недоступний. Прийняті параметри/чернетка днів не
губляться при переході до інформації чи перезапуску процесу.

Інформаційна навігація ніколи не завершує setup, не запускає план і не
направляє сторонній текст Coach. Якщо людина в цей час явно змінює власний
timezone у «Мої дані», використовуємо той самий accepted-settings writer;
повернення показує свіжі значення, стара клавіатура не відновлює попередні.

## 4. Завершення дій

| Дія | Результат і повернення |
|---|---|
| Зміна setup-параметра | Одразу коротка перевірка всіх трьох значень, без плану до підтвердження |
| Зміна активного розкладу | Актуальний розклад після canonical збереження/перепланування; історія не переписується |
| Скасування редактора | Відкинути лише незастосовану зміну, повернути останні прийняті значення |
| Зміна імені | Зберегти name_preference, повернути екран даних; Telegram-профіль не змінюємо |
| Призупинити/відновити | Актуальний стан/реальна наступна дата після виконання; не оптимістична обіцянка |
| Завершити розклад | Окреме підтвердження; після успіху — стан без активного розкладу, не erasure і не новий setup |
| Змінити формат | Пояснити заміну поточного ритму; за потреби зібрати вечірній час; не знищувати поточний до готовності |
| Запит копії/видалення | Номер, строк і статус фактично прийнятого звернення; не «готова копія» / «вже видалено» |
| Відгук | Після явного надсилання зберегти тільки поданий текст і дати правдиве підтвердження; скасування нічого не подає |

## 5. Межі та крайові випадки

- Немає активного розкладу: показати це прямо, без старої дати й кнопок
  pause/cancel неіснуючого плану. Доступний початок/продовження визначає
  наявний lifecycle/completion-контракт, не нове правило меню.
- Призупинено: немає вигаданого наступного надсилання; «Вправа зараз»
  залишається незалежною добровільною можливістю B6 за чинного доступу.
- Помилка/невідомий результат збереження: не показувати успіх, перечитати
  authority після відновлення, запропонувати повтор. Прийняті дані не скидати.
- Старе/подвійне/чуже натискання: перевірити actor, target, актуальний стан
  і revision; одна операція/один результат, не другий план чи erasure case.
- Порожні дні, неправильний час, довільний текст у кнопковому меню:
  конкретна підказка; старі значення цілі, неприпустиме не зберігається.
- При втраті доступу не блокувати власні privacy/rights/support шляхи разом
  із плановими діями. Після erasure старий callback не створює нового акаунта.
- Немає опублікованого notice/URL: чесно повідомити, надати support/rights,
  не підставляти draft замість pinned notice і не відкривати Coach без exact-version receipt. Вебreader чернетки не є notice receipt.
- Explicit self-edit не може змінити компанію, ліцензію, entitlement, історичний
  receipt чи чужий акаунт. Спірні виправлення — через існуюче звернення.
- FAQ/відгук/підтримка не отримують автоматично всю переписку. Запит щодо
  продукту не стає збереженим відгуком без явного наміру його подати.
- Звичайне повернення після перерви відновлює поточні серверні факти, а не
  запускає onboarding повторно для людини з completed setup.
