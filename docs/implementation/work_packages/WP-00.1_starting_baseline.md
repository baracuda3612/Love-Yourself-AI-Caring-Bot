## Repository conventions for the implementation program

1. `implementation/pre-mvp` is the canonical integration branch.
2. One work package is active at a time; unrelated changes do not share a
   commit.
3. Every package uses a dedicated `wp/<package>-<slug>` branch and a GitHub PR
   targeting `implementation/pre-mvp` so the configured GitHub review runs.
4. Commit subjects use the package ID where practical, for example
   `wp(00.1): establish clean implementation baseline`.
5. `IMPLEMENTED` means a stable diff exists. `VERIFIED` requires local
   acceptance plus resolution of useful GitHub review findings.
6. No archive commit is cherry-picked wholesale. Reuse is file/hunk-specific
   and must satisfy the active package contract.
7. Codex may push only the dedicated WP branch and create/update its PR. Codex
   never merges the PR and never pushes package commits directly to
   `implementation/pre-mvp` or `main`; the founder performs every merge in the
   GitHub UI.
8. `main` stays the stable release branch. After WP-09.4 and Gate G3 pass, the
   exact verified `implementation/pre-mvp` release candidate is reviewed and
   merged through the roadmap's explicit Main integration gate. Block 9 cannot
   close until that merge and release tag are recorded.
