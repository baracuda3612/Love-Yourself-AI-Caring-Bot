# WP-00.4 — Secure configuration and Railway topology

**Status:** `REVIEW`

**Date:** 2026-08-26

**Base:** `implementation/pre-mvp` at `d885bb3`

## Objective

Close the known secret and configuration failure modes, define isolated
testnet/production infrastructure, and make the Railway production
backup/restore prerequisite explicit before durable data or market launch.

## Inventory and decisions

* `.env` was removed from the current tree in WP-00.1 and is ignored, but the
  initial Git commit contains non-placeholder Telegram and OpenAI credentials.
  Both require provider-side rotation; history rewriting is not a substitute.
* No local `.env`, Railway manifest, Railway CLI/link metadata, or
  `.dockerignore` existed at package start.
* `.dockerignore` now denies the full context by default and admits only
  `app/**`, `requirements.txt`, and the exact runtime resource files. It still
  excludes credential-shaped filenames and caches below allowed directories.
* The runtime accepts exactly `dev`, `staging`, and `prod`. Missing or mistyped
  environment identity, malformed typed values, unsafe non-development
  placeholders, missing Redis, and invalid public URLs stop startup without
  echoing values.
* `DEFAULT_DAILY_LIMIT` and unused legacy model aliases were removed from the
  contract because they do not represent accepted product behavior.
* Docker is the eventual single artifact. The current `Procfile` duplication
  and the final Railway release manifest are recorded for the B9 release owner
  rather than redesigned before health, migration, and drain contracts exist.
* Testnet (`staging`) and production use isolated services and credentials. Beta
  runs one replica, one polling owner, and one scheduler writer.
* Provisioning is phased: the existing Railway contour is the only active
  pre-MVP contour and is classified as testnet. A clean production contour is
  provisioned before the first company deployment; testnet is never promoted
  or relabeled in place.

The complete variable, topology, credential, and backup contracts are in
`docs/deployment/railway_topology.md`.

## External actions and founder decision

The founder confirmed on 2026-08-26 that the historical Telegram and OpenAI
credentials were revoked provider-side. Railway Hobby was activated; replacement
`BOT_TOKEN`, `OPENAI_API_KEY`, and `REPORT_TOKEN_SECRET` values plus
`ENVIRONMENT=staging` and `DEPLOYMENT_ID=love-yourself-testnet` were applied
without disclosing secret values. PostgreSQL and Redis were restarted against
their existing volumes. The first application deployment exposed a malformed
`BOT_TOKEN` containing whitespace. The value was corrected and the application
then reached Railway `Online` / `Deployment successful` with one replica.
WP-00.4 now rejects that condition before Aiogram initialization.

The Railway environment still has the legacy dashboard name `production`.
This is a non-authoritative UI label: the applied runtime identity is
`ENVIRONMENT=staging` with `DEPLOYMENT_ID=love-yourself-testnet`, and the
contour is documented and operated as disposable testnet. A clean company
production contour will be created separately before launch.

Railway Hobby does not provide the requested native scheduled backup capability.
The founder explicitly accepts complete loss of the current zero-value testnet
data during the pre-MVP refactoring phase rather than purchasing Railway Pro or
spending more implementation time on a scratch service. A logical dump was
created and its archive/checksum validated. The attempted scratch restore was
abandoned after a temporary PostgreSQL 18 volume was attached to a PostgreSQL 17
image; the source database was not affected.

This is a time-bounded risk acceptance, not recovery evidence. Gate G1 remains
open and does not block closing this configuration package or founder-only
refactoring against disposable testnet data. Before market launch, company-user
enrollment, or reliance on durable data, the founder will provision the clean
production contour, purchase/enable Railway's production backup capability,
and complete a verified scratch restore.

## Rollback

Revert the WP-00.4 commit to restore the prior settings and Docker context.
Provider credential rotations are intentionally irreversible: restore service
by installing the replacement key, never by re-enabling a compromised key.
Railway backup deletion or production-volume replacement is not part of this
package rollback.
