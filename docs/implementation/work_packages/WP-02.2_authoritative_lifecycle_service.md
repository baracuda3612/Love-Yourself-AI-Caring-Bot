## Objective

Make `app.lifecycle` the single backend boundary for authoritative current
status, activation, terminal step transitions, expiry, pause/resume/cancel,
time reconciliation, and the stable plan-format and continuation interfaces
needed by later packages.

Every mutation re-reads persisted state under the user/aggregate lock, enforces
the current owner and entitlement facts, records a stable operation result, and
returns structured post-commit work. Persistence helpers do not send Telegram
messages or claim scheduler success.

## Audit coverage and dependencies

This package implements `LIF-01`, `LIF-09`, `LIF-16…18` and the WP-02.2 parts
of `FSM-06` and `FSM-09`. It establishes the lifecycle boundary needed by
`RT-08` and `RT-11…14` while leaving their detailed UX and schedule semantics
with WP-02.3.

WP-01.3 provides plan/step authority, row invariants, and lifecycle operation
receipts. WP-01.4 provides the event-operation boundary used by expiry. WP-02.1
removed the dead FSM, schedule-adjustment tunnel, and producerless mutation
paths before this consolidation began.

## Non-goals

This package does not implement WP-02.3 runtime-control UX, semantic time
collection, pause/resume re-anchoring, paused completion policy, or post-abort
follow-up. It does not implement WP-03.4 scheduled-delivery reconciliation or
WP-03.5 durable completion/automatic continuation. It does not add the target
content library, feature-wide instrumentation, destructive schema cleanup,
Railway migration, deployment, secret inspection, or real-data mutation.

## Implementation decisions

### One persisted-decision boundary

**Context:** live callers mixed direct status writes, guard modules, schedule
helpers, and a finalization side-effect wrapper.

**Decision:** `app.lifecycle` owns every live persisted lifecycle decision.
Builder/finalizer and time-slot modules are internal persistence/calculation
helpers only; they are not exported runtime entrances.

**Reason:** one lock and receipt protocol is reviewable and prevents different
surfaces from accepting contradictory state.

**Consequence:** `app.plan_guards` and `app.plan_pause` are deleted, and static
reachability tests reject direct status writes outside `app.lifecycle`.

### Commit before external reconciliation

**Context:** APScheduler and Telegram cannot participate atomically in the
PostgreSQL transaction.

**Decision:** lifecycle methods return typed `ExternalEffect` intents. Callers
commit the decision first, then reconciliation re-reads targets and returns
`succeeded`, `failed`, `deferred`, or `not_required`.

**Reason:** a persistence helper must not swallow an external failure and return
success, and a replay must be able to retry the same outstanding effect.

**Consequence:** activation, time changes, and cancellation expose partial
failure honestly. Expired Telegram keyboards retain `tg_message_id` until a
confirmed edit and are retried by the expiry reconciliation scan.

### Explicit deferral seams

**Context:** WP-02.2 must expose stable interfaces without implementing behavior
whose prerequisites belong to WP-02.3 or WP-03.5.

**Decision:** pause/resume schedule effects and plan-format switching return
explicit deferred results; `prepare_continuation()` validates the exact owned
completed plan without creating a successor.

**Reason:** a typed seam prevents later packages from inventing another
authority while preserving the approved dependency order.

**Consequence:** current copy no longer claims that resume already restored the
schedule. Automatic continuation and detailed control behavior remain absent.

## Data and compatibility boundary

No migration is added. Alembic head remains `20260905_event_privacy`.
`plan_lifecycle_operations` remains the durable replay ledger, while
`apscheduler_jobs` remains an external job store and never defines plan state.

`docs/implementation/wp_02_2_lifecycle_service_manifest.md`.

The package used only disposable local test databases. It did not connect to
Railway, inspect secrets, deploy, apply migrations remotely, or mutate real
data.
