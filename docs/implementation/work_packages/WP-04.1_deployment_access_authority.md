## Bounded execution contract

One access service extends the WP-01.4 tables. Restricted access records own
identity, accepted roster, entitlement, invitation and enrollment. Telegram,
`users.is_active`, URL parameters, Redis and telemetry cannot grant access.
Production identity proof uses authorization-code OIDC (Google/Microsoft) or
single-use verified email. Microsoft email claims alone are not proof of
mailbox control: email verification is required unless an already verified
stable provider subject is bound. Only current roster members receive grants.
No mailbox, directory, calendar or profile scope is requested.

Roster imports require authenticated operators, bounded JSON input, declared
mode and expected total, a stored preview, exact-count confirmation, expiry and
current-version comparison. Only confirmed full snapshots revoke by omission;
deltas contain explicit additions/revocations. Accepted versions remain as
access-only audit/rollback input. Reconciliation cadence never expires access.

Handoff tokens contain 256 random bits, are environment/key-version scoped,
hashed at rest and valid for ten minutes. Issuance is separate from roster
apply. Redemption locks current authority, consumes once and creates/resumes
one enrollment. One Telegram account and one entitlement each have at most one
active enrollment. Rebinding is operator-only after renewed identity proof;
no self-service recovery or history transfer is introduced.

All product ingress and sends check current enrollment, entitlement, commercial
period and environment. Deployment enrollment and delivery switches stay
orthogonal. Returning enrolled users need no SSO. Revocation preserves history.
Signed Telegram WebApp data authenticates time-slot callers; ownership, current
access and rate limits precede schedule mutation. Idempotency remains in the
lifecycle service. Enrollment responses never echo secrets, use no-store and
no-referrer, and have CSRF/browser binding. Request logging must exclude
enrollment query strings, bodies and authorization headers.

Testnet is founder-issued and runs the same artifact/downstream flow with
separate resources and keys. Runtime environment binding and an isolation
inventory fail closed on reused/mismatched infrastructure. Timezone resolution
uses explicit user override, otherwise deployment default in single mode;
distributed mode requires the later onboarding timezone choice before planning.

## Failure, second-order and muda matrix

| Surface | Failure / second-order risk | Bounded control and evidence |
|---|---|---|
| Roster | Wrong mode/file, malformed/empty import, stale preview, double confirmation, partial revoke, rejected/missed import | Strict validation, expected totals, exact diff confirmation, deployment lock, version CAS; atomic rollback and concurrent tests |
| Proof | Forged/expired/replayed proof, login CSRF, wrong issuer/audience/tenant/domain/subject, roster enumeration | Pinned provider endpoints, signed claims, state/nonce/browser binding, short single-use challenges, neutral replies, bounded rate limits |
| Token/enrollment | Leakage, wrong environment/deployment, replay, account substitution, issuance/revocation/concurrent redemption | HMAC digests, locked authority, uniqueness, neutral denial, one-time raw output; PostgreSQL races |
| Access/runtime | Telegram-only account, revoked/commercial-ended access, pause conflation, history loss, skipped entitlement at send | Central guard at ingress/lifecycle/send; returning/revocation/pause and B3 regression evidence |
| HTTP | Arbitrary user ID, forged/old WebApp data, cross-user/deployment mutation, enumeration, abuse | Signed caller, current enrollment, owner check, rate limit before target lookup, neutral denial; owner idempotency |
| Isolation/timezone | Test contamination, credential reuse, staging-label trust, silent Kyiv fallback | Environment inventory and DB binding, token namespace, negative config tests, default/override/distributed tests |
| Migration | Duplicate open authorities or legacy bypass survives cutover | Fail on ambiguous data, unique indexes/FKs, exact head; no fabricated legacy entitlements |
| Recovery/muda | Generic framework, retries of consumed secrets, background re-SSO | No access polling/recovery framework. Proof/token/preview expiry ends work; failed email send requires a new request. Existing B3 recovery retained |

## Migration, compatibility and rollback

Forward migration extends existing primitives and adds bounded proof/preview
state and unique current-authority indexes. No historical user receives an
invented entitlement. Stop old runtime, migrate, bind the fresh environment,
start only the exact-head artifact. No old-binary rollback. Development rollback
is drop/recreate of disposable DBs; durable rollout requires Gate G1 and a
reviewed restore/forward-fix plan. No Railway/company enrollment or testnet
history promotion is authorized here. Release/medical/device gates remain open.

Verification starts from 431 default passes / 167 opt-in skips, 66 PostgreSQL
completion and 13 runtime-control scenarios. PostgreSQL runs only in newly
created disposable databases. Freeze the candidate and whole-diff surface map,
obtain independent fresh-context read-only review, fix confirmed scoped defects,
rerun affected evidence, then push/PR to `implementation/pre-mvp` and inspect
configured automatic review. Founder alone merges.
