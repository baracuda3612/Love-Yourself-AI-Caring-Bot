## Fixes and practical behavior

**SETUP-01. Earlier setup text must finish deterministic routing before a
later confirmation can complete setup.** ActorIngressMiddleware shares one
private-actor lock across message/callback outer middleware, before asynchronous
filters. Weak lock references avoid retaining an unbounded actor registry.
PostgreSQL remains ownership/idempotency authority. The text route releases
its lock after commit and before Telegram/model I/O; a slow Coach does not
hold menu/rights actions behind the model call. The lock is scoped to the
existing single polling process, not a distributed event-ordering framework.

**CAL-01. Reapplying an already accepted calendar choice repairs scheduler jobs
from stored timestamps.** The unchanged branch now returns reconciliation
work instead of an empty effect list. It does not increment plan version,
reanchor dates, alter due/attempt facts or create a new calendar receipt.
Calendar failure copy tells the user to reopen settings and apply the same
choice. The existing reconciler rechecks actual current plan/user facts under
its canonical lock, including pause and report-blocking rules.

**SCHEMA-01. The verified subject's export includes retained menu_input.** The
existing export model list now includes MenuInput and the same user predicate.
Expired/canceled editor rows still retained in the database are included too.
No new rights procedure, migration or retention policy is introduced.
