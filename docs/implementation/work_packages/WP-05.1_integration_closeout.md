## Delivered contract

* Coach reads authoritative plan, schedule, exercise, entitlement and notice
  context. Tool exposure follows the current state and is checked again at
  execution; mutations retain locked authorization. Outgoing replies recheck
  access. Read-only context uses a bounded DB worker and an unlocked
  access/notice snapshot so one participant's slow work does not hold the
  shared event loop or deployment lock.
* The final exercise starts durable successor preparation; source close and
  successor creation commit together. Preparation retry, first-exercise
  scheduling and summary delivery recover independently. A
  pending, failed or late summary never blocks successor exercises. Genuine
  user pause, enrollment and entitlement remain authoritative. Recovery work
  is bounded by owner; re-enabling delivery wakes exercise and completion
  recovery. Delivery controls remain exceptional incident safeguards.
* `get_plan_status` reports the factual cycle transition after the last
  exercise. It names a future exercise time only when an actual schedule has
  one; it reports the current operator delivery state without inventing an
  active delivery or remaining exercise.

disposable PostgreSQL runs of **73 passed** for completion and **42 passed**

findings fixed and no new confirmed P0–P2 in the reviewed paths. Its overall

not measured. The [automatic PR review](https://github.com/baracuda3612/Love-Yourself-AI-Caring-Bot/pull/275)
also completed on that head with zero findings. A zero-finding review does not
close unexecuted release scenarios.

**NOT_PROVEN:** live Telegram/model behavior, DB-pool saturation, real
DB-operation deadlines, sustained throughput for a large cohort, and the
release artifact/device journey. Keep these as release evidence work in
WP-09.1/09.2/09.3/09.4, with cost/latency and model behavior in WP-05.3/05.4.
Capacity thresholds must derive from the expected cohort and measured
headroom, not an arbitrary fixed user count. Existing
[A43-01…06](WP-04.3_acceptance_followups.md) remain open for their assigned
owners. These unproven checks are not new WP-05.1 defects.
