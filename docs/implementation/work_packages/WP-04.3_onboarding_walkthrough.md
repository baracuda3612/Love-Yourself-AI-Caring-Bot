# WP-04.3 — Авторська перевірка сценаріїв і меж погодження

2026-10-30. Перевірено чинний roadmap WP-04.3/B6, handoff, copy/editor
drafts і поточні Telegram entrances. Це аналіз сценаріїв перед реалізацією,
не незалежний code review, не тест живого бота й не доказ PostgreSQL/race/DST
поведінки. Поточний `/start` ще не виконує погоджений setup; макет також не
замінює backend. Жодних нових тестових PASS для implementation не заявлено.

WP-04.3 не залежить від завершення B6 для власного локального acceptance:
roadmap WP-06.2 сам залежить від WP-04.3. Інтеграція погодженої кнопки

мертвої кнопки до готовності її сервісу. Не створювати циклічну WP-залежність
і не реалізовувати тимчасовий другий sender у WP-04.3.

## Розбір переходів на рівні дизайну

Позначення **визначено** означає, що поведінку можна реалізовувати за вже
погодженими правилами. Воно не означає, що код існує або тест пройшов.

| Сценарій / маршрут | Очікуваний результат | Додаткове рішення засновника |
|---|---|---|
| Вступ → налаштувати час → `14:34` | Одразу три рядки перевірки, Пн–Пт, налаштований стандартний пояс | Не потрібне: визначено |
| `00:00`, `23:59`, інший коректний HH:MM | Прийняти без штучного company-window; далі реальний canonical schedule | Не потрібне: DG-01 вирішено |
| `99:99`, `24:00`, `14:75`, сторонні літери | Підказка формату; той самий крок; не зберігати невалідне | Не потрібне: визначено |
| Фото/голос замість часу | Попросити час текстом; не викликати модель, не втрачати крок | Не потрібне: реалізаційний fallback |
| Перевірка → змінити → назад до підтвердження | Ті самі три прийняті значення | Не потрібне: визначено |
| Редактор часу → новий коректний час | Лише час змінений; відразу перевірка | Не потрібне: визначено |
| Редактор часу → те саме значення | Відразу перевірка без зайвого циклу підтверджень | Не потрібне: визначено |
| Ненадісланий текст → скасувати зміну | Старий прийнятий час; draft Telegram недоступний боту, інструкція просить надіслати | Не потрібне: назву/семантику скасування погоджено |
| Редактор днів → кілька перемикань → застосувати | Один непорожній прийнятий набір; відразу перевірка | Не потрібне: визначено |
| Усі дні вимкнені → застосувати | Попросити хоча б один день, залишити редактор; старий прийнятий набір цілий | Не потрібне: пропорційна валідація |
| Перемикання днів → скасувати → відкрити знову | Незастосовану чернетку відкинуто; показати прийнятий набір | Не потрібне: визначено |
| UTC-перегортання → скасувати | Пояс не змінився | Не потрібне: визначено |
| Обрати ручний цілий UTC-зсув | Одразу перевірка; local HH:MM і дні цілі, пояс фіксований | Не потрібне: визначено |
| Повернути стандартний пояс | Named default із сезонними правилами; ручне перевизначення знято | Не потрібне: визначено |
| Переглянути стандартний пояс під час сезону | Читання не конвертує named timezone у fixed UTC; показати «Київ»/назву налаштованого поясу | Не потрібне: уточнення засновника вже було |
| Немає початкового timezone | Не вгадувати, не створювати план; дати вибір. Для звичайного входу це помилка конфігурації deployment, не нове обов'язкове запитання всім | Не потрібне: реалізаційна перевірка |
| FAQ/privacy/support із редактора | Відповідний фіксований текст, потім відновлюваний поточний крок; не відправляти до Coach | Погодити самі короткі тексти одним пакетом |
| Сторонній текст на перевірці/меню параметрів | Підказати вибір кнопками; не трактувати як приховану зміну часу | Не потрібне: реалізаційний fallback |
| Закрила Telegram / процес перезапустився | Прийняті параметри в PostgreSQL; `/start` повертає актуальний setup/перевірку | Не потрібне: тест персистентності |
| Два повідомлення/стара клавіатура/старе підтвердження | Стара взаємодія не перезаписує новішу; актуальний крок/перевірка | Не потрібне: revision/ownership tests |
| Зміна не збереглася / результат запису невідомий | Не показувати успіх; повтор/скасування, перечитати DB після відновлення | Не потрібне: fault-injection tests |
| Доступ відкликано або акаунт видалено | Немає setup/плану/відновлення через стару кнопку; зберегти наявний rights/support шлях | Не потрібне: security/regression tests |
| Підтвердити двічі, також конкурентно | Один перший SHORT-план, одна completion-фактографія | Не потрібне: транзакційні PostgreSQL tests |
| Коміт плану відбувся, scheduler reconcile не завершився | Чесний pending стан і recovery того самого плану, без нового плану чи вигаданої дати | Не потрібне: existing lifecycle contract |
| Після scheduling відповідь Telegram втрачена | Повернення показує фактичний поточний план; немає повторної активації | Не потрібне: recovery test |
| Час уже минув / неробочий день / обрані інші дні | Promise із фактичного першого finalized step, не з попереднього anchor | Не потрібне: scheduling boundary tests |
| Сезонний перехід default / ручний UTC | У default зберігається місцева година; ручний UTC не змінюється сезонно | Не потрібне: політику погоджено, потрібні тести |
| Почала/не почала першу добровільну вправу | Setup завершений в обох випадках; план працює; кнопка входить у B6 | Не потрібне для WP-04.3; delivery сценарії — B6 |

Авторський висновок: нових необхідних продуктових розвилок у цих сценаріях
не виявлено. Існують обов'язкові реалізаційні перевірки, які ще не виконані.
Малі формулювання технічних помилок готує виконавець; не відкривати кожен
такий випадок як окреме питання засновнику. Суттєву зміну поведінки,
privacy/safety promises чи accepted capability винести окремо з конкретним
прикладом, а не нескінченним списком гіпотетичних винятків.

## Що реально потребує участі засновника

1. Оглянути й погодити конкретний дизайн **user menu**: назви/групування,
   основні екрани й confirmations. Виконавець готує пропозицію, а не просить
   засновника спроєктувати все з нуля. Політики lifecycle вже мають власників.
2. Оглянути компактний пакет фіксованих **FAQ/privacy/support** текстів.
   Опублікований юридичний notice не підміняється цим погодженням.
3. Оглянути представлення **employee enrollment web → Telegram**, яке прямо
   входить у WP-04.3. Базову access/security архітектуру не перепогоджуємо.

Найближча продуктова робота — user menu. Non-happy-path implementation і
тести — відповідальність виконавця; delivery «Вправи зараз» зараз не
відкривати як обов'язкове погодження цього WP.
