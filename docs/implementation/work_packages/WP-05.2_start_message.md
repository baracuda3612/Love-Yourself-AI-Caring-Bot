## Bounded result loop

* Accept at most one allowlisted tool call per user turn. Parse and validate
  its name and arguments against current user, plan, mode and action state.
  Recheck authority at execution, including any state change since model
  context was built.
* Return a strict structured backend result. Make at most one second model
  pass with tools disabled. The response may describe only the confirmed
  result and other verified context; a failed or uncertain action is never
  voiced as success. On malformed call, execution failure or second-pass
  failure, send a deterministic factual fallback. No recursive tool chain.
* Add bounded, user-scoped PostgreSQL reads for confirmed deliveries and
  outcomes by local day or limited period, canonical instructions for a
  selected exercise, feedback by exercise and date/period, and factual counts
  for the previous cycle. Count missing feedback separately. Keep the final
  completion-report format in WP-07.4.
* Resolve an explicit Telegram Reply only to its referenced message in the
  current user's chat. Pass verified user/assistant message, delivered
  exercise or completion-summary context in the initial model request. Mark
  missing or unverified references unavailable.

## Acceptance evidence

Exercise success, soft failure, exception and uncertain outcomes through the
supported user entry point; invalid tool names/arguments; changed state
between context and execution; second-pass failure; one-call ceiling and
tools-disabled proof; user-language response grounded in actual backend
receipts. Cover bounded reads with ownership, day/timezone and period limits,
missing feedback, and no cross-user data. Cover valid and stale/missing
Telegram Reply references in the same and another chat. Verify deterministic
product delivery and WP-03.5 independent continuation still work without the
model. Use disposable PostgreSQL where persistent behavior matters and retain
exact test results and limitations for review.

Keep semantic search of old chat and automatic recovery of expired action
intent in the backlog. Do not fold WP-05.3 outage/cost work, WP-05.4 full
regression, or WP-09.4 live-device/capacity acceptance into this package.
Operator delivery disable is an exceptional incident path, not a normal
assistant workflow. The [roadmap](../pre_mvp_implementation_roadmap.md#current-package)
continues to own package status and release gates.
