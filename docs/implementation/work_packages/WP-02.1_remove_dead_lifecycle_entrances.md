## Objective

Delete the complete schedule-adjustment tunnel and every other audited dead
lifecycle entrance without expanding the lifecycle service, changing live
plan-format behavior, or performing a destructive database contract step.

## Preconditions and bookkeeping

WP-01.4 is `VERIFIED`. Founder merged PR #255 as
`22c72fd2e0d1c9ea3401b88be8f473bd0df3e736`; first commit `4e28e06` recorded
that closeout and marked Block 1 complete before WP-02.1 implementation began.

The package used repository evidence only. It did not connect to Railway,
inspect secrets, migrate a deployed database, deploy an application build, or
mutate real data.

## Bounded implementation plan

1. Prove the missing producers/callers for the schedule tunnel, legacy worker
   envelope, first-plan wrapper, retired states, and generic FSM helpers.
2. Delete each closed subsystem with its registrations, Redis keys, imports,
   and tests rather than retaining compatibility stubs.
3. Preserve and test the target replacement where it already exists; record
   the named later-package owner where product behavior is intentionally not
   implemented yet.
4. Retain executable import/reachability checks and compare the full suite with
   the exact founder-merge baseline.

## Removed surfaces

* the schedule-adjustment dispatcher, four handlers, callback keyboards,
  timeout callbacks, Redis methods/keys, scheduler constants/job helpers,
  `_resume_plan_if_paused`, and two dedicated test modules;
* the unused aiogram Redis FSM storage factory and runtime state/guard package;
* `generated_plan_object`, `plan_updates`, and `transition_signal` handling,
  their inert persistence/preview helpers, and legacy-only tests;
* `app/plan_adaptations.py`, whose last callers were the dead tunnel/envelope;
  `AIPlanVersion` remains inert storage for WP-08.1 rather than being dropped;
* `create_first_plan`, `_auto_drop_plan_for_new_flow`, `IDLE_ONBOARDED`, and
  `IDLE_DROPPED` runtime representations;
* producerless plan-action preview callbacks and optional response-envelope
  fields;
* Telegram completion-report `start_plan:` buttons, without adding a handler.

## Replacement and deferral boundary

| Removed entrance | Preserved target behavior or named owner |
|---|---|
| Schedule-adjustment tunnel | `change_day_time` and `change_evening_time` update authoritative schedule data and reschedule active jobs without changing lifecycle mode. |
| Generic FSM guard/commit | `app.lifecycle` owns locked, idempotent plan/step operations and `derive_current_mode()`. WP-02.2 expands that service; this package does not. |
| Legacy worker mutation envelope | Coach emits text or an allowlisted `tool_call`; the orchestrator executes only the deterministic registry. |
| First-plan wrapper | Canonical `create_plan()` already enforces first-plan SHORT; deterministic onboarding calls it directly in WP-04.3. The current mock onboarding never called the removed wrapper. |
| Retired idle states | Onboarding progress plus current plan status derive the four current modes. WP-01.3 already cleared legacy `users.current_state`; physical column/constraint cleanup remains WP-08.1. |
| Telegram `start_plan:` CTA | Removed because it had no handler. Automatic same-format continuation remains WP-03.5. |
| Adaptation snapshot writer | Pause/resume and time changes remain authoritative runtime operations. Physical `AIPlanVersion` removal remains WP-08.1. |

The canonical `schedule_adjustment` event name introduced by WP-01.4 is not
the removed FSM tunnel and remains available for later feature instrumentation
under WP-07.1.
