## Objective

Complete the deterministic runtime-control behavior above the authoritative
`app.lifecycle` boundary established by WP-02.2. Invalid input or context must
fail before persistence, accepted decisions must produce one replayable result,
and post-commit scheduler work must be reported truthfully without requiring an
LLM to execute or confirm it.

## Dependencies and preserved invariants

WP-02.2 is verified and remains the persistence authority. This package
preserves its ownership, entitlement, user-row locking, immutable receipt,
idempotency, commit-before-external-effect, and scheduler-fencing contracts.
It adds no schema migration or competing lifecycle state.

The accepted product contract requires semantic local `HH:MM` validation,
plan-aware evening behavior, pause/resume from the next remaining working day,
deterministic cancellation, user-requested follow-up only after abandonment,
truthful progress facts, and one atomic 7↔14 format switch. The first evening
time is collected before a SHORT→MEDIUM switch mutates the current plan.

## Bounded implementation plan

1. Centralize semantic time and lifecycle-context validation in
   `app.lifecycle`; keep Coach schemas and tool filtering as defense in depth.
2. Make pause remove future jobs after commit while preserving child state;
   make resume atomically re-anchor every remaining open day from the next
   selected working day, recompute expiry, and reconcile one exact plan job set.
3. Keep cancellation as one authoritative abandoned result, close every open
   step once, and expose partial scheduler cleanup honestly. Permit manual
   follow-up activation only when the latest owned plan is the accepted
   abandoned source state.
4. Derive status from persisted delivered/open/terminal step facts and thread
   plan type, evening availability, and pending MEDIUM collection context into
   deterministic Coach tool filtering.
5. Replace the deferred format-switch seam with one locked transaction that
   validates all prerequisites, closes the source steps, creates the
   replacement, and records one replayable switch receipt; any builder or
   finalizer error rolls the whole transaction back.
   Reconcile both old-job removal and new-plan scheduling only after commit.
6. Map applied, rejected, deferred, superseded, partial-failure, and replay
   outcomes explicitly through runtime tools and orchestrator copy. Add
   outcome-level regressions across lifecycle, tools, orchestrator, scheduler,
   time-slot API, and Coach filtering.
7. Run focused and expanded affected slices, full-suite baseline comparison,
   compilation/import/reachability/diff checks, and a disposable PostgreSQL
   persistence/rollback rehearsal. Freeze a stable candidate for a separate
   fresh-context read-only review.

## Independent-audit remediation

The independent read-only audit of candidate
`75a262b630f150b703d0a636ef000e84de9e5c79` reported two P2 caller-truth
findings. Both are accepted and fixed in one bounded remediation delta:

- **F1:** a composite `/user/time-slots` retry can contain one superseded slot
  and one newly persisted slot. The HTTP 409 contract now reports
  `mixed_time_slot_outcome`, aggregate `saved: true`, and a per-slot applied,
  replayed, deferred, superseded, or partial-failure state. A failed scheduler
  proof for the persisted slot is visible and requests retry with the same
  idempotency key; the API never reports `saved: false` for that mixed commit.
- **F2:** the first-evening switch cascade now distinguishes a persisted
  replacement from failed post-commit reconciliation. It tells the user that
  the 14-day plan exists and preserves the pending source key. The final F3
  remediation below makes the promised fresh-message retry executable without
  creating a second replacement. The direct-switch partial-failure copy
  remains consistent.

Fail-before-fix tests reproduced both audit symptoms. After remediation, the
focused API/orchestrator slice passed `26 passed`; the expanded affected slice
passed `109 passed`. The full suite finished `300 passed, 21 failed, 3
skipped`: the same 21 inherited completion CTA/report/metrics failures and the
three opt-in PostgreSQL tests skipped by the ordinary run. Compilation,
configured imports, Alembic head (`20260905_event_privacy`), authority search,
and `git diff --check` passed. The remediation changes only HTTP/result
reporting and orchestration retry copy; it does not alter persistence,
transaction, migration, receipt, or scheduler-effect boundaries, so the
PostgreSQL rehearsal was not repeated.

The final independent audit of remediation candidate
`8e647a2f331f551dcb5962bacac15b6d88cf6e27` accepted F1 and the truthful part
of F2, then reported **F3 P2**: a normal fresh Coach call has a new call ID, so
the old cascade tried to record the evening preference again and failed the
now-MEDIUM lifecycle guard before reaching the retained switch receipt.

F3 is accepted and fixed with an internal receipt-gated recovery entrance.
`app.lifecycle.recover_plan_format_switch()` first locks the entitled user and
requires the exact existing `switch_plan_format` source/target receipt; it can
never create unrelated switch intent. It then delegates to the original
atomic switch function, which returns `needs_evening_time` for a legitimate
not-yet-collected request, completes an already-authorized interrupted switch,
or replays a committed replacement and its post-commit effects. Missing,
drifted, and stale sources reject or return superseded truth. The orchestrator
tries this recovery before processing a new evening-time call, clears an
invalid/stale pending key, and bypasses the now-invalid SHORT-only guard after
the replacement has committed.

The F3 regression failed before the fix with distinct `evening-7` and
`evening-8` call IDs, then passed while proving that the second call never
invokes `record_evening_time` and reuses only `switch-7`. Lifecycle tests cover
missing and matching receipts, and an unrelated pending source is rejected
without calling the time mutation. Final evidence: `113 passed` in the expanded
affected slice; `304 passed, 21 failed, 3 skipped` in the full suite, with the
same inherited completion CTA/report/metrics failures; `3 passed` in the
disposable PostgreSQL rehearsal, now including missing-source rejection and
receipt-gated committed-switch replay. Compilation, configured imports,
Alembic head (`20260905_event_privacy`), authority search, and
`git diff --check` passed.
