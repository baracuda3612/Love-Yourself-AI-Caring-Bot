# WP-00.3 — Make the local environment reproducible

**Status:** `VERIFIED`

**Date:** 2026-08-26

**Base:** `implementation/pre-mvp` at `5197284`

## Objective

Create one reproducible Python environment and an honest test baseline before
application refactoring begins. This package changes environment compatibility
only; it does not repair product behavior owned by later work packages.

## Implemented environment contract

* Python 3.12 is the supported local line; local bootstrap, runtime, and Docker
  are pinned to Python 3.12.14.
* `requirements.in` and `requirements-dev.in` contain reviewed direct
  dependencies. Compiled `.txt` files pin all transitive versions.
* `make bootstrap` cleanly rebuilds `.venv` from the dev lock so an older
  interpreter cannot survive underneath a newer system Python.
* `make test-collect`, `make test-targeted`, and `make test` are the canonical
  collection, package, and full-suite commands.
* `make audit` checks the installed environment for known vulnerabilities.
* Test collection supplies synthetic local configuration and requires no
  production credential or external network call.
* `make services-up` starts isolated PostgreSQL 16 and Redis 7; `make
  services-down` removes the containers and their ephemeral data.

Runtime upgrades were selected for compatibility and security rather than
freshness alone. In particular, aiogram 3.31 removes the vulnerable aiohttp
line inherited through aiogram 3.5, while FastAPI/Starlette, Jinja2, and
python-dotenv move to patched lines. OpenAI remains at 2.9.0 because no
security or application compatibility evidence justifies a major API migration
inside this package. Redis stays on major version 5 and Uvicorn on the 0.34
line to avoid unrelated major behavior changes.

`httpx2` is dev-only because current Starlette uses it for `TestClient`; the
application's runtime HTTP contract remains unchanged.

  its only consumer.

  pip upgrade;
* collection completed with 223 tests and no import error;

Service verification:

* Docker Compose configuration validated;
* PostgreSQL 16 reached `healthy` and accepted connections on its isolated
  test port;
